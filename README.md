# 瞬刻摄影工作台 · Stillmark

> 定格一瞬，刻下永恒。

瞬刻摄影工作台，给独立摄影师和小团队用的轻量策划小工具。从情绪板上的一缕灵感，到分镜表里的每一格画面，再到提案与拍摄日程，最后走进实拍现场——把一瞬间，刻成永恒画面。零散想法、参考图和执行细节稳稳收在一处；小项目一个接一个，慢慢沉淀成属于你的策划档案。

**适合谁**：独立摄影师、2–5 人小团队——想把一个案子从灵感、分镜、提案带到拍摄现场，但不想为空白模板和 SaaS 账号买单。
**不适合谁**：大型剧组，以及需要合同、收款、交付画廊或多人实时协作的场景；那些交给专业工具更划算。
**怎么开始**：双击 `shotflow.html` 即可用；要在手机上使用，把 `shotflow-app/` 部署到静态托管并安装为 PWA。数据只存在你自己的设备里。

---

## 一、核心架构

```
情绪板 / 场景 / 服化道 / 器材   →   分镜表（数据中枢）   →   客户提案
        （素材层）                  （一切挂载点）          执行手册
                                       ↓                  提案 HTML 文件
                                  拍摄日模式（含日程流程）
```

分镜表是整个应用的中枢：每条分镜可挂 1-3 张参考图（来自项目的**参考图库**，与情绪板精选分离）、关联场景、带日期时段与预计时长。素材挂完，方案即成；现场执行、文档输出都从分镜表派生。

## 二、功能清单

### 1. 多项目看板（首页）
- 按生命周期分 6 列：灵感期 → 策划中 → 待拍摄 → 后期中 → 已交付 → 已归档
- 顶部统计条：进行中项目 / 今日拍摄 / 逾期待办 / 总预算；「★ 已收藏 N」一键进入全局收藏视图
- 示例项目带金色「示例」角标，只读；点「复制为我的项目」得到可编辑副本（图片无需重传）
- 项目卡片显示客户、拍摄日倒计时（"还有 N 天"）、分镜进度条、待办数、逾期红标
- **全局搜索**：按项目名 / 客户 / 主题 / 风格 / 分镜 / 沟通记录检索；「全部 / 进行中 / 已归档」筛选（已归档同时含已交付与已归档）

### 2. 项目工作台（7 个页签，按 策划→执行→落地 分组）

| 分组 | 页签 | 说明 |
|------|------|------|
| 策划 | **概念** | 主题、调性、受众、用途、创意阐述，输入即自动保存 |
| 策划 | **情绪板** | 文字 / 色彩 / 精选图片（仅表达整体基调与视觉方向）；「上传精选图」或「＋ 从参考图库精选」才会加入，分镜上传的执行参考图**不会**自动混入；图片压缩 800px 存入 IndexedDB；所有素材可打多标签（逗号分隔），支持按标签筛选与词表重命名 / 删除；每条素材可 ☆ 收藏 |
| 执行 | **分镜**（中枢） | 挂 1-3 张参考图（我的素材 + 姿势图库）+ 场景 + 机位 + 光线 + 时长；**不填时间**（由日程自动排期）；**拍摄日改为下拉选择（Day 1 · 11-18 / ＋ 新日期…）**，列表按拍摄日分组（每组标题带条数与合计分钟）；一次可上传多张（最多挂 3 张，其余仅入参考图库；上传图不会进情绪板 / 客户提案），灯箱支持上一张 / 下一张 / 更换 / 移除；✎ 行内编辑 6 项（名称 / 时长 / 场景 / 机位 / 光线 / 备注）；场景下拉可「＋ 新建场景…」行内建场景并自动选中；拖拽排序、跨日期改期；关键词搜索；每条分镜可 ☆ 收藏 |
| 执行 | **日程** | **多日拍摄**：顶部 Day 1 / Day 2 … tab 切换 + 「＋ 添加拍摄日」（默认取最后一天 +1）与「删除本日」；切 tab / 顶部日期框**只切查看、不登记拍摄日**（某日首次产生内容——新增分镜、新增手填环节、跨日拖拽——才登记）；信息卡「Day 1 · 首个拍摄日」改日期：原 Day 1 无内容则**替换**首日，有内容则**追加**为 Day N 并提示「Day 1 仍有 N 条安排，未改动」；拍摄日时间轴：流程节点（集合/化妆/转场/收工…）+ 当日分镜合并展示，分镜行带「分镜」标签；**已登记的拍摄日首次进入自动生成「集合 09:30–10:00」与「收工」**（收工时间 = 当天最晚结束 + 15 分钟，只读并带「自动」标记）；分镜从「最大(10:00, 集合结束)」起顺序排期并避开所有环节；插入/编辑环节后**其后的环节链式顺延、分镜整体避让**，被顺延的环节临时标「已顺延」，重叠处标红「时间重叠」；**当天排到 24:00 之后的分镜（含其后所有分镜）自动跨到次日并从次日 max(10:00, 集合结束) 重新起排**（次日自动成为拍摄日，最多 7 轮，超限提示检查时长）；环节可 ✎ 行内编辑；**日出/黄金时刻/日落/暮光自动计算** |
| 执行 | **清单** | 场景选址 / 服化道 / 器材，可勾选、可 ✎ 行内编辑，三类条目均可 ☆ 收藏 |
| 落地 | **预算** | 费用明细 + 总预算 / 已付 / 待付统计（支出红色），每条可 ☆ 收藏 |
| 落地 | **协作** | 待办事项（负责人/截止日/逾期标红）+ 沟通记录（电话/微信/见面，时间倒序）；两类条目均可 ✎ 行内编辑与 ☆ 收藏 |

八类条目的收藏汇总在「★ 已收藏 N」视图中按项目 → 模块分组展示；点「定位 ›」跳回原页签并高亮 3 秒，不跨项目复制。

### 3. 拍摄日模式（灵魂功能）🎬
- 深色全屏，日程节点与分镜按时间合并成一条流
- **自动高亮"当前该做什么"**，参考图随手看
- 52px 大按钮单手打勾，逾期或时间重叠时一键「整日顺延 1 小时」——当天所有环节（含集合、收工）与分镜整体后移 1 小时再重排；当天只有分镜没有环节时会提示先在日程里插入环节；超出当天 24:00 会提示改期
- 顶部显示当日日出 / 黄金时刻 / 日落 / 暮光时间，安排逆光、剪影镜头有依据
- 前一天 / 后一天快速切换

### 4. 四种文档输出
- **客户提案**（弹窗预览，可打印 / 存 PDF）——以统一的「画廊扉页」封面开篇：策划名、主题、出镜模特、拍摄日期、工作室落款自动填入，底纹为可印刷的双层菱形暗纹
- **发送提案文件**：生成独立 HTML 文件（图片内嵌、封面与样式全内嵌，微信直接发给客户）
- **拍摄通告单（Call Sheet）一页纸**：当日时间线 + 场景 + 器材 + 沟通要点，天气与联系电话留白现场填写；打印后直接给化妆师 / 助理
- **执行手册**：分镜 + 流程 + 场景 + 清单 + 待办 + 预算，打印带到现场；分镜表参考图 112×112（窄屏 84×84，打印仍 112），图文对照

### 5. PWA 装到手机桌面
- 独立窗口、离线可用、镜头造型图标
- 版本更新时自动提示「发现新版本 → 刷新」

### 6. 数据安全（v4 重点）
- **项目主数据已迁至 IndexedDB**（库 `shotflow`，store `projects`），内存缓存 + 合并写入，不再受 localStorage 的 MB 级配额限制；图片仍在 store `images`
- 首次打开自动把旧 localStorage 数据迁移到 IndexedDB 并清理旧 key；v3 的 refId 也会自动转为 refIds
- **导入前二次确认**：弹窗显示将覆盖的项目数与名称；单项目备份则作为**新策划案追加**，不会误覆盖
- **项目级导出**：项目页「导出此案」只导出当前策划案及其图片，便于交接、归档和版本留档
- 全量导出 JSON 含全部图片（含示例内嵌 SVG）；清空二次确认；≥30 条备份提醒（不计入示例项目）

## 三、文件夹结构

```
摄影策划工具/
├── shotflow.html            # 主程序（由 src/ 构建产出的单文件，全内联零依赖）
├── shotflow-manifest.json   # PWA 清单
├── shotflow-sw.js           # Service Worker（离线缓存版本见文件内 CACHE 常量）
├── icon-192.png             # PWA 图标 192×192
├── icon-512.png             # PWA 图标 512×512
├── legacy/                  # 历史版本归档（v1 模块表单版 photo-planner.html）
├── docs/                    # 设计文档（系统设计 / 类图 / 时序图）
├── overview.md              # 功能索引（开发视角）
├── README.md                # 本说明
├── 竞品调研与升级方案.md    # 竞品分析与版本升级方案（含二次分析复核）
├── src/                     # 源码（P3 拆分）：shell.html + styles.css + js/01..05（分段）
├── scripts/                 # build.mjs / verify-build.mjs / sync-app.mjs
├── tests/                   # 测试：logic.test.mjs（纯函数）+ e2e/app.spec.js（Playwright）
├── package.json             # 构建/测试脚本与依赖（Playwright / ESLint / Prettier）
├── playwright.config.js     # E2E 配置（含零依赖静态服务器）
├── eslint.config.js         # ESLint flat config
├── .prettierrc              # Prettier 配置
└── shotflow-app/            # 部署快照目录（与线上同步的副本）
```

> **源码与构建（P3）**：`shotflow.html` 现在是由 `src/` 多文件源码**构建产出**的单文件交付物（仍可双击即用、零运行时依赖）。
> 修改功能时请改 `src/`（样式改 `src/styles.css`，逻辑改 `src/js/0x-*.js`，骨架改 `src/shell.html`），然后运行 `npm run build` 重新生成 `shotflow.html`。
> `npm run verify:build` 校验交付物与源码一致（CI 自动执行）——若有人直接改了 `shotflow.html` 而没改源码，会在此处被拦截。
> `npm run verify:version` 以 `package.json` 的版本为真源，校验 README / overview / lock 的「当前版本」标注一致（CI 自动执行）——升级版本时只需改 `package.json`（+ `npm install` 更新 lock）并按提示同步文档标注。SW 缓存版本是独立序列，由 `sync:check` 保证两端一致。
>
> **部署副本同步**：构建后运行 `node scripts/sync-app.mjs` 同步到 `shotflow-app/` 再部署；`--check` 校验两端一致（CI 自动执行）。
>
> **测试与规范**：`npm install` 后，`npm run test:logic` 跑逻辑测试，`npm run test:e2e` 跑浏览器 E2E（首次需 `npx playwright install chromium`），`npm test` 两者都跑；`npm run test:perf` 跑规模压测（含性能门禁）；`npm run lint`、`npm run format:check` 检查代码规范。CI 有 5 个 job（构建一致性/逻辑/规模压测/E2E/副本同步）。

## 四、使用说明

### 本地打开
双击 `shotflow.html`。本地 `file://` 下 PWA 安装与 Service Worker 不可用（浏览器安全策略），其余功能全部正常。

### 手机安装（PWA）
把仓库中的 `shotflow-app/` 部署到任意静态托管（GitHub Pages、Netlify 等），用手机浏览器打开部署后的 HTTPS 地址。源码不含任何平台访问码；若所用平台要求 `sharecode` 一类访问参数，请在部署环节注入，不要写回仓库源码。

- **安卓 Chrome**：打开后点看板页「安装到桌面」，或菜单 →「添加到主屏幕」
- **iPhone Safari**：分享按钮 →「添加到主屏幕」
- 安装后离线可用；数据存手机本机，换设备前先「导出备份」

### 推荐使用流程
1. 看板页「+ 新建项目」
2. **概念**页签：主题 / 出镜模特 / 调性 / 受众 / 用途（主题与模特自动进入提案封面）
3. **情绪板**页签：上传精选图或从参考图库精选、记文字灵感、取色，上传时给素材打标签（逗号分隔，如 `逆光, 中景, golden hour`）
4. 项目信息卡填工作室署名（封面落款）、拍摄地点 + 经纬度（或点城市快捷键，如南京）→ 日程页有日落时间，封面有落款
5. **分镜**页签：逐条添加，上传 / 挂参考图（自动入参考图库，不会污染情绪板）+ 场景 + 时段，拖手柄排序；可按标签快速挑参考图
6. **日程**页签：加集合 / 化妆 / 转场 / 收工等流程节点
7. **清单**与**预算**页签补全
8. **协作**页签记待办和沟通要点
9. 「客户提案」预览后可导出 HTML 发客户确认；「拍摄通告单」一页纸打印给团队；「执行手册」打印带走
10. 拍摄当天进**拍摄日模式**，逐条打勾；时间重叠或延误时级联顺延
11. 交付后把项目状态改为「已交付」或「已归档」；看板「已归档」筛选同时含已交付与已归档
12. 想收藏某个灵感 / 分镜 / 日程条目，点该行 ☆；到看板或项目页「★ 已收藏 N」统一查看与定位

### 数据迁移
- 换设备 / 交接：项目页「导出此案」生成单案 JSON（含图片）；新设备「导入」会**自动作为新项目追加**，不覆盖现有数据
- 整机备份：看板页「导出备份」→ 全量 JSON；新设备「导入」弹窗确认后覆盖恢复
- 旧版本数据首次打开时自动迁移到 IndexedDB，无需手动操作

## 六、迭代记录

- **v2** `shotflow.html`：分镜中枢架构 + 多项目看板 + 拍摄日模式 + IndexedDB + PWA

## 七、已知限制
- 示例项目只读，需「复制为我的项目」后才能改；收藏不跨项目（定位只跳转，不复制条目）
- **v10.4**：分镜 / 拍摄用图默认只进参考图库，不会自动进入情绪板或客户提案；需要放进提案请到情绪板「从参考图库精选」
- **v10 多日**：仅在「该日首次有内容」时登记拍摄日（只是翻看某天不算），避免拍期清单被随手翻的日期污染；删除拍摄日要求该天没有分镜、也没有手填环节（自动生成的集合/收工不算）
- **v10 行为变化**：老项目**首次**进入某个拍摄日期时，当天的分镜时间会被整体重排到「最大(10:00, 集合结束)」起的顺序链，历史上手填的 `slot` 不再生效（这是「时间自动排期」的必然结果，不是数据损坏）；已被 `dayInit` 记录的日期不会重复补集合/收工，删掉后也不会自动复活
- **v10 自动跨日**：跨日后的分镜从次日 10:00 重新起排（每天结构一致），**不支持跨零点连续排期**；单条分镜时长超过一整天（>14 小时）或连续跨满 7 天时会停止并提示检查时长；删除拍摄日要求该天没有分镜、也没有手填环节（自动生成的集合/收工不算）
- 时间冲突检测为相邻事项重叠检查，不做复杂资源/人员冲突；节点顺延只在「本轮插入/编辑的那个环节」之后生效，anchor 自身位置永远尊重用户输入（重叠时只标红）；顺延不会跨越当天 24:00，超限需手动改到次日；超过 23:59 的分镜时间会被格式化为 23:59 并提示溢出
- 示例图是内嵌 SVG，离线可看，不联网；姿势图库仍需联网空闲同步
- 日落时间为 NOAA 近似算法 + 城市中心坐标估算，误差几分钟，未计入地形/天气，仅作排期参考
- 不做实时协作与 CRDT 同步（定位是低并发小团队）；交接靠项目级导出
- 本地 `file://` 打开时 Service Worker 不注册、无法安装 PWA；PWA 安装需 HTTPS 或 localhost
- 任何平台访问码均不入库，需在部署侧配置
- AI 自动打标签为接口预留，当前默认关闭、不发起任何网络请求；外部素材仅提供外链，不内置、不随项目导出
- shisei 姿势图库为本地缓存，仅在页面可见、联网且空闲时按 24 小时间隔自动检查；可暂停 / 清除；导出备份不包含图库数据，分镜里的图库引用在新设备需重新同步后显示原图
