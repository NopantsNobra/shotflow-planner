更新：2026-11-27。本文记录当前能力、尚未验证的事项和后续顺序；完成状态以代码、测试和可复现记录为准。

- **ZIP 资产包 v1**：项目包与分镜包支持二进制图片、Schema 校验、预览和确认导入；旧 JSON 导入保持兼容。CI 覆盖 Chromium、Firefox、WebKit，并包括容量、取消和回滚场景。

## 产品边界

- 项目、图片默认保存在浏览器本机；工作台不要求账号、云同步或模型服务。
- 文件包是用户主动选择的交接方式。ZIP 不是加密格式，可能含照片、拍摄地点或客户资料；导出与传输前应确认内容及授权。
- Agent 只可生成候选文件。正常导入器负责校验、预览和持久化；提示词、图片描述和包内文字不构成读取本地数据、上传、部署或直接写入的授权。
- 内置模型接入保持关闭。引入前需另行评估数据范围、上传确认、供应商能力、取消机制和结果审核。

## 交接契约

- `projects` 包新建一个或多个完整项目；`shots` 包可创建精简项目，或在预览时选择目标项目追加。
- 容器、数据和业务类型分别版本化。ZIP 清单记录数据与图片路径、字节数及 SHA-256；图片以独立二进制条目保存。
- 分镜引用的场景、参考图和必要关系必须随包闭合；无关项目数据、凭据和未授权图片不应进入包。
- 导入需先校验结构、语义、图片及引用；用户确认前不写入。冲突、配额、并发或取消失败不应污染已有数据。
- Schema 由运行时代码生成；运行 `npm run schemas:check` 检查公开 Schema 是否漂移。新增格式版本时应增加明确的适配与真实导入回归，不把内部 IndexedDB 结构当作永久外部契约。

## 后续顺序

### 1. 排查 Safari ZIP 导入

用户报告 Safari 提示“格式不正确”。代码中的“文件格式不正确，导入失败”提示只会在 ZIP 未被识别、文件随后按旧 JSON 解析失败时出现；正常 ZIP 解析错误会显示“导入失败：…”。确认实际提示、Safari 加载的应用版本、ZIP 文件名/扩展名、导入入口和具体测试包，再区分旧版 PWA 缓存、文件交接/识别路径与归档读取问题。Chrome 已实机导入成功；不能据此推断 Safari 侧的文件内容损坏。

### 2. 独立 Agent 盲测

只提供公开指南、任务提示词、Schema、示例、用户需求和获准使用的参考图，不提供源码。分别生成分镜包与项目包；通过正常 UI 导入并检查图片、场景、分镜、日程、刷新持久化和错误恢复。记录模型、输入、文件摘要、步骤、结果与失败，不将模型自述视为验收证据。

### 3. 真机迁移

覆盖 iOS Safari、iOS 主屏幕 PWA、Android Chrome、离线刷新、跨 origin 交接、应用更新/后台恢复和存储受限。先备份测试数据，并记录设备、浏览器版本、包摘要、可见结果与恢复情况。

### 4. 依据证据维护

128 MiB 附近的设备容量、极大项目虚拟化、旧/新标签页并存、清空与恢复并发、拖拽/筛选边界及真实屏幕阅读器按用户影响排序。未出现实际瓶颈前不拆分 IndexedDB 项目主记录，也不增加 MCP、HTTP API 或实时协作后端。
