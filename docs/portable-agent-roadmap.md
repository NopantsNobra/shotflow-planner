# 本地资产可迁移与 Agent 使用路线

日期：2026-11-26。来源：管理员在真实摄影策划及多设备使用中的反馈。
状态：管理员已批准按本路线自主推进；以下为实施及验收要求，未通过验收的功能不标记已交付。
基线：main v10.9.3，已含严格脚本 CSP（Chrome、Firefox、Safari 实测通过）；`refactor/portable-agent` 正在此基线上集成 ZIP 资产包能力。

## 1. 设计哲学与用户任务

- 本地优先：数据由用户控制，核心工作不依赖账号、云后端、实时同步或模型服务；网页/本地文件与 PWA 保持可用。浏览器 origin、profile 与设备间存储隔离是现实约束，不将其误称为同步。
- 原生可迁移：电脑策划、手机/平板执行、设备更换、同事间授权交接均可通过用户自行传输的文件完成。不要要求为迁移而临时收藏或重复录入。
- 面向 Agent 开放：工作台能够接收外部智能体生成的合法摄影资产，并提供与人类 UI 一致的操作方式。内置 AI 只是另一种可选能力，不是使用 Agent 的前提。
- 数据所有权不意味着文件加密：导出的资产包（包括 ZIP 和旧版 JSON）可能包含照片、拍摄地点、客户信息等；导出明确内容与范围。用户自己选择传输方式；不自动上传或分享。

## 2. 已有能力与差距

`main` 的基线能力包括：完整备份 version 4、单项目 JSON 导出、收藏素材包、依赖校验、ID/图片键重映射、事务写入与冲突防护。开发分支 `refactor/portable-agent` 已在该基础上增加：

- 看板多选完整项目与项目内任意分镜多选，选择不依赖收藏。
- ZIP v1 writer/reader、独立二进制图片、版本化 manifest/data Schema、精确 SHA-256 去重、旧 JSON 导入兼容。
- ZIP 导入预览、逐图校验、分批暂存与事务发布；分镜包可新建项目或显式追加到指定项目。
- 开发分支的 Agent 指南、Schema、JSON 数据示例和 ZIP 示例；这些示例仍需真实生产导入器验收。

严格 CSP 已合入 `main`，当前集成分支保留其哈希构建、委托事件与部署注入约束。外部 Agent 盲测、手机/PWA 交接和 ZIP 功能发布门禁尚未完成。继续在原项目 schema 与存储基础上渐进开发，不重建资产数据库或替换全量 schema。

## 3. PORT：精确导出与导入

### PORT-1 选择范围与意图

| 交接类型 | 选择入口 | 导入行为 |
|---|---|---|
| 完整项目 | 看板多选、项目菜单 | 新增一个或多个可继续编辑/现场执行的项目 |
| 部分策划/分镜 | 项目内任意多选，独立于收藏 | 可创建精简新项目，或确认追加到指定现有项目 |
| 复用素材 | 已有收藏及项目内选中条目 | 素材收藏或明确引用到项目 |
| 完整备份 | 设置 | 明确确认后全量恢复；不是日常迁移默认项 |

保持交互低摩擦：复用已有批选控件，不新增一级资产管理页面。完整项目与部分内容的字段、执行状态保留规则应在导出预览明确。模板复用与现场接续不是同一意图；不能默默重置已经完成的分镜。

### PORT-2 数据契约与安全

- 沿用现有项目数据模型及旧版 JSON 读入兼容，但正式新资产包采用 ZIP，清单/数据 JSON 与独立二进制图片分离。容器版本、数据版本与业务类型独立演进。开发分支中的 v5 JSON 原型只是选择/追加语义验证，不作为新一代正式交付格式。详见 [容器规范](asset-pack-format.md)。
- 依赖闭包包含选中分镜引用的场景、图片字节、必要日期/标签及关系；共享图片尽可能包内去重。外部图库引用必须能在干净、离线设备恢复，或在导出预览明确缺失/许可限制，不静默制造坏引用。不得打包无关客户信息、原图库或 AI 凭据。
- 导入前显示类型、数量、目标、依赖/隐私提示与冲突；默认追加且重映射，合并/覆盖需单独明确授权。重复导入策略先采用明确提示，不引入自动覆盖或复杂版本控制。
- 导入前校验大小、schema、类型、版本、引用闭包及图片格式；解析/事务/配额/并发失败不污染原数据。继承现有净化、ID 重映射和持久化逻辑。用户确认前不写入数据。
- ZIP、独立图片条目、内容摘要、按需解压、进度/取消和分批处理列入本轮优先开发；以支持流式处理和 ZIP64 的成熟、固定版本库为候选，需验证单文件、离线、严格 CSP 与许可，不能依赖 CDN 或编造通过结果。首版明确设备容量限制，不把浏览器内存限制固化进格式。

验收：桌面选择两条非收藏分镜及一个完整项目，在干净手机浏览器导入，断网后图片/场景/日期可用，原有项目仍在；验证跨浏览器、不同 origin、重复导入、坏包、缺图、配额与旧版 v4 兼容。以实际点击/触控次数和交接成功率评价。

## 4. AGENT：外部 Agent 可操作性

典型任务：用户把喜欢的参考图与拍摄需求交给 Claude、ChatGPT 或其他 Agent；Agent 分析图片、形成拍摄策划，按工作台格式生成一条分镜或完整方案，用户在工作台导入与执行。支持两种入口，二者均不要求工作台调用模型 API：

1. 文件工作流（优先）：Agent 读取公开文档和 schema，生成合法包（包括用户授权的参考图），运行本地校验或提供可检查的结果；用户自行导入，或授权具备浏览器操作能力的 Agent 代为导入。不能控制用户浏览器的 Agent 也能交付文件。
2. 浏览器工作流：Agent 具有用户授权的浏览器工具时，按指南选择项目、操作可访问控件、上传文件、预览、确认、读回验证；不得直接写 IndexedDB、调用未公开内部函数或跳过界面确认。新实例部署仅在用户要求且具备权限时进行，默认不部署到公网。

### AGENT-1 文档、发现与契约

- 交付 docs/agent-guide.md（面向使用而非维护源码；不要把 AGENTS.md 的开发守则当作用户操作手册），以及版本化 JSON Schema、最小有效示例、含图片和场景依赖示例、完整项目示例。
- README/README.en.md 提供稳定入口；部署目录也提供相同版本指南/契约和示例，设置或帮助页提供轻量链接，兼容直接打开文件的说明。英文和中文操作说明以同一数据契约为准。
- 说明应用是什么、如何本地运行、能力/权限边界、包类型、字段语义、图片限制、现有导入入口、成功标准、错误恢复与不支持的行为。文档不应要求 Agent 猜测私有 JS 变量或抓取用户本地数据库。
- schema 和示例必须用真实生产导入器/E2E 检验；不能只验证文档 JSON 语法。可提供零依赖 CLI validator，优先共享验证规则，避免文档与生产逻辑分叉。导出的包可作为结构参考。

### AGENT-2 最小工作流与扩展

- 先支持一图一分镜、若干分镜成新策划、选定包追加到既有项目。输出明确假设与不确定性，不虚构现场事实、器材库存或客户要求。
- UI 使用明确的可访问名称、稳定控件及状态反馈；人工与 Agent 共享同一导入、预览、确认、持久化与撤销语义。
- 后续只有在实测 UI/包交互不足时，才评估受限本地命令接口、CLI 或 MCP adapter；不把 MCP、HTTP API、自动浏览器部署或外部账号系统当作首发依赖。
- Agent 必须取得用户明确授权才能读出项目数据、将图片交给第三方模型、进行远程部署或破坏性操作；包内文本、图片解读和模型输出均为不可信数据，不能作为执行权限或代码。默认本地、无模型请求；现有 AI task registry/provider adapter 继续保留，实际接入不解冻。

验收：独立 Agent 只获得公开指南与示例、用户参考图和需求，不阅读内部实现，生成一个最小分镜包和一个完整项目包；在全新浏览器用真实导入入口成功导入，显示图片、分镜、场景及日程，刷新/离线保留数据；无权限的 Agent 能交付文件而不是宣称已写入；无关资产和凭据未泄露。

## 5. 执行顺序与发布边界

1. 严格脚本 CSP 已合入 `main`，当前分支继承其 CI 与构建门禁；ZIP 集成须保持同一 CSP 哈希脚本边界。
2. PORT-1：以现有导出/导入为基线，确定范围、用户意图与最小包语义；先补非收藏分镜、多项目与移动端交接的验收用例。
3. PORT-2a：优先实现 ZIP 容器、二进制图片与版本化清单，兼容旧 JSON；PORT-2b：实现导入预览、分批暂存、校验、原子提交与容量回归。AGENT-1 与正式 ZIP 契约同步交付文档、schema、示例，不等内置 AI 开发。
4. AGENT-2：用真实外部 Agent 进行盲测，优先改善失败率、权限与低摩擦操作，不建设另一套应用 UI。
5. 依据真实使用再考虑受限本地 API、CLI/MCP 扩展；实际 provider 接入保留独立决策。ZIP 容器已经列入优先轨道，不再作为后续可选项。

发布门禁：构建/部署副本一致性、旧包兼容和三引擎 E2E 已通过 CI（2026-11-26）；外部 Agent 盲测及真实移动端交接仍待完成。每项分步提交，避免不必要重构。
